# deadreckon run output — schema **v1.0.0**

**Frozen.** Reviewed by the dashboard's author before freezing; the changes
that came out of that review are listed at the bottom. Breaking changes
from here bump the major version — see [Versioning](#versioning).

Produced by:

```bash
python run_detectors.py --json examples/sample-run.json
```

Two examples ship with the repo:

| File | What it is |
|---|---|
| [`examples/sample-run.json`](../examples/sample-run.json) | **Real** dump of the seeded fixture: 5 models, every detector state, both a flagged and a fully-clean model. |
| [`examples/sample-run-edge-cases.json`](../examples/sample-run-edge-cases.json) | **Synthetic.** States the fixture can't reach without changing the demo matrix: a model with a finding that is *not* at risk, and a fully unassessable model. Generated by [`examples/generate_edge_cases.py`](../examples/generate_edge_cases.py) through the same serializer. |

Serialization lives in `detectors/report.py`, the single source of truth
for this shape.

## Top level

| Field | Type | Notes |
|---|---|---|
| `schema_version` | string | `"1.0.0"`. Fail loudly on an unexpected **major**; minor/patch are additive. |
| `run` | object | Run metadata. |
| `detectors_meta` | object | Human-readable titles/descriptions per detector, so labels stay in sync with backend semantics instead of being hardcoded in the UI. |
| `scoring` | object | The constants this run used — render scales and legends from these, don't hardcode. |
| `models` | array | **Already in ranked order.** Render as-is; do not re-sort. |

### `run`

| Field | Type | Notes |
|---|---|---|
| `assessed_at` | ISO 8601 string | The instant assessed against. |
| `clock_overridden` | bool | **The dashboard MUST honour this.** `true` means the run used an overridden clock (`DEADRECKON_NOW`/`--as-of`) — a test or rehearsal run, not a live one. Mark it visibly; presenting a clock-shifted run as current would be exactly the kind of quiet misrepresentation this project exists to prevent. |
| `datahub_base_url` | string | Base used to build every `url`/`*_url` field. |
| `models_assessed` | int | |
| `datasets_examined` | int | |
| `detectors` | string[] | `["D1","D2","D3"]`. |

### `detectors_meta.{D1,D2,D3}`

| Field | Type |
|---|---|
| `title` | string — e.g. `"Frozen training source"` |
| `description` | string — one sentence |
| `weight` | number — same value as in `scoring.detector_weights` |

### `scoring`

| Field | Type | Notes |
|---|---|---|
| `max_possible_score` | number | Currently `3.0`, and genuinely reachable — a model sits on it in the real sample. Use as the denominator; **this is not a 0–1 scale**. |
| `detector_weights` | object | Per-detector confidence weight. |
| `environment_weights` | object | Serving-stage weights. |
| `latent_risk_floor` | number | Blast radius used for an undeployed model. |
| `severity_thresholds` | object | `{"HIGH": 2.0, "MEDIUM": 0.7}`; below MEDIUM is `LOW`. |
| `statuses` | string[] | All possible detector states. |

## `models[]`

| Field | Type | Notes |
|---|---|---|
| `urn` | string | Stable identity — key off this, not `name`. |
| `name` | string | |
| `url` | string \| null | Deep link into DataHub (URN percent-encoded). |
| `group` | object | `{urn, name, url}` of the `mlModelGroup`. Any may be `null`. |
| `serving_stages` | string[] | e.g. `["PROD"]`, `["STAGING"]`, `[]` when undeployed. **Genuinely multi-valued** — see the note below. |
| `score` | number | `0.0` when nothing was found. Not normalized. |
| `severity` | string | `HIGH` \| `MEDIUM` \| `LOW`. |
| `blast_radius` | number | Worst serving stage reached (a max, not a sum). |
| `finding_count` | int | Total across detectors; also the ranking tie-breaker. |
| `coverage` | object | See below. |
| `detectors` | object | Keyed `D1`/`D2`/`D3` — findings live here. |
| `tags` | object | `{at_risk, unassessable}` — **read these, don't derive them.** See below. |
| `assessment_document_urn` | string | The Model Risk Assessment document written to the graph. **No URL:** document entities have no working profile route in this DataHub version (see `NOTES.md`), and a link that 404s is worse than none. |

### `models[].tags` — read, do not derive

| Field | Meaning |
|---|---|
| `at_risk` | Mirrors the `undertow:at-risk` tag on the model in DataHub. |
| `unassessable` | Mirrors `undertow:unassessable`. |

**`at_risk` is gated on `severity` (MEDIUM or HIGH), not on finding
count.** A model can have findings and still not be at risk — an
undeployed model with a D2 finding scores `0.5` → `LOW` → `at_risk:
false`. Deriving the flag as `finding_count > 0` or `score > 0` will
paint a red flag where the graph has none, and the dashboard will
disagree with DataHub. Both divergent cases are in
`sample-run-edge-cases.json`.

### `models[].coverage`

How much of the model could actually be assessed. Deliberately separate
from the score: a detector that lacked the metadata to run is neither a
pass nor a risk, and folding "unknown" into the score would destroy the
meaning of both.

| Field | Type | Notes |
|---|---|---|
| `conclusive` | int | Detectors that reached a verdict. |
| `total` | int | Detectors run. |
| `label` | string | Pre-rendered `"2/3"`. |
| `fully_covered` | bool | `conclusive == total`. |
| `unassessable` | bool | `conclusive == 0` — no verdict at all. |

**A clean model with `fully_covered: false` is not the same as one with
`fully_covered: true`.** Make that visible; collapsing them is exactly the
silent failure this project exists to catch. An unassessable model scores
`0.0` just like a clean one — `coverage` is the only thing distinguishing
"nothing wrong" from "nothing checked".

### `models[].detectors.{D1,D2,D3}`

| Field | Type | Notes |
|---|---|---|
| `status` | string | `PASS` \| `FINDING` \| `INSUFFICIENT_DATA`. |
| `conclusive` | bool | True for `PASS` and `FINDING`. |
| `subjects_checked` | int | Datasets/features/transformations conclusively checked. |
| `finding_count` | int | |
| `findings` | array | **Findings live here**, under the detector that raised them — no client-side join to populate a matrix cell. For "all findings on this model", concatenate over the three known keys. |
| `coverage_gaps` | array | Grouped by aspect — see below. |

### `models[].detectors.{D}.coverage_gaps[]`

| Field | Type | Notes |
|---|---|---|
| `aspect` | string | The absent aspect/field, e.g. `operation.lastUpdatedTimestamp`. Names what to go emit, so the gap is actionable. |
| `count` | int | How many subjects are missing it. |
| `subjects` | array | `{urn, url, detail}`. |

Grouped by aspect because one aspect missing across four datasets is one
thing to fix, not four identical rows — and the graph writeback groups it
the same way, so both surfaces agree on shape.

### `models[].detectors.{D}.findings[]`

| Field | Type | Notes |
|---|---|---|
| `detector` | string | Same as the parent key; kept so a finding stays self-describing when lifted out. |
| `summary` | string | Full sentence, for the detail view. |
| `subject` | string | Compact "what/where" (e.g. `customers.credit_limit missing 3d`), for tables and cards. |
| `subject_urn` | string \| null | The upstream entity that broke — **not** the model. |
| `subject_url` | string \| null | Deep link to it. |
| `evidence` | object | **Shape varies by detector** — see below. |
| `lineage_path` | array | Ordered upstream → downstream — see below. |

#### `evidence` — switch on `detector`

`evidence` has a **different shape per detector**. This is stated plainly
rather than papered over: any UI rendering findings richly has to branch
on `detector` anyway, so pretending the object is opaque would be a false
promise. Normalizing it into a common envelope is the better long-term
design and is deliberately deferred — it is a refactor, not a contract fix.

| Detector | Keys |
|---|---|
| **D1** | `dataset_urn`, `dataset_last_updated`, `frozen_days`, `latest_training_run_urn`, `latest_training_run_at` |
| **D2** | `feature_urn`, `dataset_urn`, `source_column`, `schema_changed_at`, `missing_days`, `latest_training_run_urn`, `latest_training_run_at` |
| **D3** | `transformation_dataset_urn`, `feature_source_dataset_urn`, `definition_changed_at`, `changed_days`, `latest_training_run_urn`, `latest_training_run_at` |

Rendering generically (a key/value definition list) is fine and stable;
`subject` and `summary` exist so the common case needs no branching.

#### `lineage_path[]` — the ignition point in context

Ordered upstream → downstream, ending at the model. Node shape:

| Field | Type | Notes |
|---|---|---|
| `type` | string | `dataset` \| `mlFeature` \| `dataProcessInstance` \| `mlModel`. |
| `urn` | string | |
| `name` | string | Display name. |
| `url` | string \| null | **Only `dataset` and `mlModel` carry URLs** — those two routes are verified against a live DataHub. `mlFeature` and `dataProcessInstance` routes are unverified in this version, and the `document` entity turned out to have no working page at all, so we emit the URN alone rather than a link that might 404. |
| `ignition` | bool | The node where the problem originates. Exactly one per path. |

Shapes by detector:

- **D1** — `dataset(ignition) → dataProcessInstance → mlModel`
- **D2** — `dataset(ignition) → mlFeature → dataProcessInstance → mlModel`
- **D3** — `dataset(ignition, the dbt/Spark node) → dataset(source) → dataProcessInstance → mlModel`

This is deliberately **raw**: identity, a display name, and the ignition
flag. No edge labels, no per-node timestamps, no enrichment — all of that
would need graph lookups the run does not otherwise make, and the path as
emitted costs nothing because the detectors already had every node in
hand. If the lineage view needs more, that is a scope decision, not a
serialization tweak.

## Notes for the dashboard

1. **`models` is pre-sorted** by `(score desc, finding_count desc)`. Ranking is one decision, made in the backend.
2. **Score is not 0–1.** Always show it against `scoring.max_possible_score`.
3. **Three states, not two.** `INSUFFICIENT_DATA` must be visually distinct from `PASS` — "we couldn't check" is not "it's fine". This is the core claim of the project.
4. **Read `tags`, don't derive them** (see above).
5. **Honour `run.clock_overridden`** (see above).
6. **`serving_stages` vs the URN.** Every seeded entity's URN ends in `PROD` — that is DataHub's *catalog* fabric, not where the model serves. `serving_stages` is the real deployment, and the two can legitimately disagree. The field is genuinely multi-valued: the backing structured property has `MULTIPLE` cardinality, so a model may serve from more than one stage at once, even though no seeded model currently does. Handle `[]`, one, or several.
7. **Empty `findings` is a first-class result**, not an error state. A fully covered model with no findings is the strongest thing the agent can say.

## Scope limits (deliberate)

- **No pagination.** One run is one document, all models included. Fine at demo scale (5 models); a production instance with thousands would need chunking. Called out so it reads as a scope decision rather than an oversight.
- **No incremental/delta output.** Each run is a complete snapshot.
- **`evidence` is not normalized** across detectors (see above) — deferred deliberately.

## Versioning

`schema_version` is semver over the *contract*, not the data.

**Breaking (major bump):** removing a field; renaming a field; changing a
field's type; changing the meaning of an existing value; adding a new
value to a closed enum the UI switches on (`severity`, detector `status`,
`lineage_path[].type`); changing sort order or any documented invariant
(e.g. "exactly one ignition node per path").

**Non-breaking (minor):** adding a new optional field; adding a new
detector key under `detectors`/`detectors_meta`; adding keys to a
detector's `evidence`; adding a new entity type that only ever appears
with `url: null`.

Consumers should reject an unexpected **major** and tolerate unknown
fields within a matching one.

## Changes from the v0 draft, after consumer review

| Change | Why |
|---|---|
| `missing[].missing` → `coverage_gaps[].aspect` | The old key was overloaded — a field named `missing` inside a `missing` array. |
| Coverage gaps grouped by aspect | Was one row per subject, repeating the aspect name. The graph writeback already grouped it; the two surfaces now match. |
| Findings moved under `detectors.{D}.findings` | Was a flat array, forcing the UI to filter by detector for every matrix cell. |
| Added `group.url` | Was URN-only, so linking the group meant hand-rolling the route. |
| Added `detectors_meta` | Detector titles were about to be hardcoded in the UI. |
| Added `lineage_path` per finding | The ignition point alone can't draw the path; the nodes were already in memory and cost nothing to emit. |
| `evidence` documented as per-detector | The draft claimed it was an opaque bag while the lineage view required branching on it. |
| Added edge-case example | The real dump never showed a finding on a not-at-risk model, and the reviewer reasonably derived the wrong rule for `at_risk`. |
| Documented `clock_overridden`, `serving_stages` cardinality, pagination limits, versioning rules | All ambiguous or unstated in the draft. |

Declined, with reasons: dropping `tags` (they mirror the graph and cannot
be safely derived); dropping `assessment_document_urn` (it is the evidence
that writeback happened, which the project is judged on); adding
`blast_radius_stage` (`serving_stages` already carries the names); trimming
derivable fields like `coverage.label` (payload size is not a constraint here).
